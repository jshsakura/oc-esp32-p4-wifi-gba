# oc-esp32-p4-wifi-gba

Retro-Go firmware for a handheld built into a Game Boy Advance shell, around a Waveshare
ESP32-P4-WIFI6 module.

## The hardware

| | |
|---|---|
| MCU | ESP32-P4, dual RISC-V at 360MHz, 32MB PSRAM, 32MB flash |
| Wi-Fi | ESP32-C6 on the module |
| Display | D310N9362V0 — 3.1" 480x800 IPS, ST7701S, MIPI DSI, mounted rotated |
| Audio | ES8311 codec and NS4150B amplifier, both on the module |
| Input | 10 GBA buttons plus two rear paddles, over two TCA9554 expanders |
| Storage | microSD on the module, SDMMC 4-bit |
| Power | IP5306, LiPo, and the shell's original slide switch |

240x160 goes up 3x to 720x480 inside the panel's 800x480. Integer, so nothing blurs, and the
result measures 60.48 x 40.32 mm against the original GBA's 61.2 x 40.8 — close enough that a
stock-sized opening hides the pillarbox.

## Targets

| | |
|---|---|
| `oc-gba` | the handheld |
| `oc-gba-devkit` | same firmware for a bare Waveshare dev board, buttons on header pins |
| `esp32p4` | the base's original target, kept building as a reference |

The dev board is most of the real thing: the panel is DSI and plugs into the module's own FPC
connector, and the SD slot, codec and radio are all on the module too. What the carrier board
adds is buttons, the battery path and the shell.

## Building

```sh
. ~/esp/esp-idf/export.sh          # ESP-IDF v5.5
python3 rg_tool.py --target oc-gba-devkit build-img
python3 rg_tool.py --target oc-gba-devkit --port /dev/ttyACM0 install
```

See [docs/FLASHING.md](docs/FLASHING.md) for wiring, SD card layout, recovery, and an honest
list of what is most likely to be wrong the first time a panel is plugged in.

## Pin definitions come from the board, not from a person

`tools/pinmap_from_kicad.py` reads the fabricated `.kicad_pcb`, maps each header pad to the
GPIO behind it, and `--check` fails when the board and `config.h` disagree:

```sh
python3 tools/pinmap_from_kicad.py <board.kicad_pcb> --check
```

This is not ceremony. It has already caught the paddle buttons landing on a different
expander than assumed, and a display line being deleted — each of which would have shown up
on hardware as one dead button or a dark panel, which is the worst way to find out.

## Notable differences from the base

- **Boot-loop rescue.** Three boots that fail to stay up for fifteen seconds skip stored
  settings and the stored boot target — between them the likeliest reason a device stops
  booting — and offer a way out.
- **A missing display no longer hangs the device.** DSI writes never return with nothing on
  the other end of the ribbon, so the panel init runs on its own task with a deadline and the
  rest of the system carries on without it.
- **Auto-save on a timer**, because a hard power switch gives no chance to save on the way
  down. It points the boot config at what it wrote, so the next boot resumes there.
- **PICO-8**, via [FAKE-08](https://github.com/jtothebell/fake-08) as a seventh app partition.
  Carts go in `/roms/p8/`, either `.p8` or `.p8.png`. The backend is written to be upstreamable
  and lives in the submodule at `external/fake-08/platform/esp32p4-retro-go/`; PICO-8's 4bpp
  screen is handed to retro-go as an 8-bit paletted surface, so nothing converts colours and
  `pal()` is free.
- **Korean**, with the font subset from the translations and regenerated by the build.
- **ES8311 audio**, **ESP32-P4 overclocking**, and the three emulators the base had disabled
  (DOOM, Mega Drive, MSX).
- **Boot splash** from `/boot/logo.png` and `/boot/boot.wav`. Nothing is shipped; it shows
  whatever you supply, and adds no delay when there is nothing there.

## Status

Runs on hardware: boot in 384ms, SD, audio, launcher, fonts, recovery. Waiting on the panel
and the carrier board: display output, buttons, and anything that needs either.
[docs/BRINGUP.md](docs/BRINGUP.md) is the checklist, and what can be verified without either.
